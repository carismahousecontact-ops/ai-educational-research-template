# سياسة اعتماد 21st.dev في تصميم Antigravity

## القرار

اعتماد [21st.dev](https://21st.dev/) كمصدر استكشاف وانتقاء للمكونات والأنماط البصرية، وليس كنظام تصميم جاهز أو قالب يُنسخ بكامله.

الموقع يوفّر مكتبة مجتمعية من مكونات React وTypeScript وTailwind، وقوالب وثيمات وخلفيات ومؤثرات، مع معاينات حية وطرق تسليم عبر prompts أو shadcn CLI. هذا يجعله مناسباً لاستكشاف حلول واجهات محددة داخل مكدس المشروع الحالي (Vite + React + TypeScript + Tailwind CSS v4)، مع ضرورة التحقق من التوافق الفعلي لكل عنصر قبل اعتماده.

## ما نبحث عنه للمشروع

الأولوية ليست للمؤثرات اللافتة بحد ذاتها، بل للمكونات التي تخدم وظائف Antigravity:

| المجال | الأنماط المرشحة | معيار الاختيار |
|---|---|---|
| الصفحة الرئيسية | Hero sections، عناوين متحركة باعتدال، خلفيات دقيقة | توضيح هوية البحث والابتكار دون منافسة المحتوى |
| التنقل | Navigation، mega menus، command/search patterns | وصول سريع إلى أقسام المنصة ومساراتها |
| البحث والمعرفة | Search interfaces، filters، tabs، data cards | تحسين اكتشاف الأدلة والموارد |
| الوكلاء والذكاء الاصطناعي | AI chat، prompt/input patterns، activity states | تفاعل واضح، حالات تحميل وخطأ، وإظهار حدود الوكيل |
| المشاريع والمختبر | Cards، grids، galleries، timelines | عرض المشاريع والتجارب وسياقها ومرحلتها |
| التقييم والأدلة | Charts، comparison tables، score/rubric patterns | قراءة النتائج دون تضليل بصري أو ازدحام |
| التفاعل الدقيق | Buttons، tooltips، dialogs، accordions | اتساق وإمكانية وصول وتحسين الاستخدام |

## ضوابط الانتقاء

1. افحص المعاينة الحية على سطح المكتب والهاتف قبل الاختيار.
2. سجل اسم العنصر ورابط صفحته ومؤلفه وتاريخ الفحص والترخيص/شروط الاستخدام.
3. لا تفترض أن جميع عناصر 21st.dev تحمل الترخيص نفسه؛ تحقق من ترخيص العنصر وشروط المنصة وأي مصدر تابع له.
4. لا تنسخ الصور أو GIF أو الفيديو أو لقطات المعاينة أو البيانات الوصفية من المنصة إلى منتجنا دون إذن مناسب.
5. عند استخدام عنصر منشور على 21st.dev، التزم بشروطه، بما في ذلك الإسناد والرابط الظاهر إلى صفحة العنصر متى اشترطت الشروط ذلك.
6. لا تعِد توزيع مكونات الغير أو تنشرها كمكونات أصلية لنا دون امتلاك الحقوق.
7. لا تستخدم scraping أو جمعاً آلياً لمحتوى المنصة؛ الاختيار والفحص يدويان عبر واجهتها.
8. لا تضف مكتبة أو حزمة كاملة لمجرد عنصر واحد. فضّل نسخ المكوّن اللازم إلى المشروع بعد مراجعة مصدره وتبعياته، إذا كان الترخيص يسمح.
9. افحص React/TypeScript وTailwind CSS v4 وواجهات shadcn/Radix المطلوبة. عالج اختلافات Tailwind أو CSS tokens صراحةً، ولا تفترض التوافق لمجرد أن العنصر React.
10. لا تكرر أنماط الحركة الثقيلة أو الخلفيات المتحركة؛ حافظ على أداء الجوال، احترام prefers-reduced-motion، وإمكانية الوصول بلوحة المفاتيح وقارئات الشاشة.
11. حافظ على هوية Antigravity: بحثية، علمية، مستقبلية، هادئة وواثقة. تجنب مظهر SaaS عام أو استعراض المؤثرات على حساب وضوح المعرفة.
12. اختبر حالات الاستخدام الفعلية: التحميل، الفراغ، الخطأ، البيانات الطويلة، النص العربي واتجاه RTL، والشاشات الصغيرة.

## مسار اعتماد أي عنصر

- **اكتشاف:** البحث عن نمط يحل مشكلة حقيقية في صفحة محددة.
- **معاينة:** فحص النسخة الحية والسلوك والتجاوب.
- **تدقيق:** المؤلف، الترخيص، شروط الاستخدام، التبعيات، الأمان وإمكانية الوصول.
- **تكييف:** مطابقة ألوان وخطوط ومسافات وحالات التصميم في المشروع.
- **نموذج أولي:** تطبيق معزول أو فرع مستقل، لا استبدال مباشر للمكون الحالي.
- **مراجعة:** مقارنة قبل/بعد وفق معايير قبول واضحة.
- **اعتماد:** دمج بعد موافقة صاحب المشروع والتحقق من البناء والمسارات.
